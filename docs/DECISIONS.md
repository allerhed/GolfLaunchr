# Decisions

Product defaults live in [spec/03-decisions.md](spec/03-decisions.md). This file records engineering/tooling decisions.

| Date | Decision | Why |
|---|---|---|
| 2026-10-11 | Opus plans and reviews; Sonnet implements. Default session model is Sonnet. | Cost: planning/review is the high-judgement, low-volume work. |
| 2026-10-11 | XcodeGen (`project.yml`) generates the gitignored `.xcodeproj`. | Clean diffs for agents, no merge conflicts in pbxproj. |
| 2026-10-11 | Local SPM packages hold logic (Domain, Analytics, ...); app target holds SwiftUI only. | Fast `swift test`, agents work in small contexts. |
| 2026-10-11 | Single developer: commit and push to `main`, no PRs, no CI. `scripts/verify.sh` is the gate. | macOS CI runners cost money and add nothing for one developer. |
| 2026-10-11 | Spec split into per-feature files under `docs/spec/`; `_full.md` kept unread. | ~38k tokens per full read vs 1-3k per feature. |
| 2026-10-11 | Bundle id `com.allerhed.golflaunchr` (placeholder, brand-independent per spec section 1). | Spec requires a stable id independent of the final brand. |
| 2026-10-11 | Scripts set `DEVELOPER_DIR` to Xcode.app when `xcode-select` points at Command Line Tools. | Avoids needing sudo. |

| 2026-10-11 | The `planner` agent is the spec "coordinator" (sole owner of contract changes, with user approval). | Spec WP01 requires one contract owner. |
| 2026-10-11 | Club contract extended beyond spec section 6: `name` (= spec "label"), `brand?`, `model?`, `sortOrder`, `loftRevision`, plus `ClubSnapshot` (id, name, loftRad?, loftRevision). Resolves the F08 plan question Q1. **Pending owner confirmation** (planner role). | F08 needs brand/model/ordering; loftRevision lets future estimation know which loft a shot used. Additive, optional fields only. |
| 2026-10-11 | Shot JSON contract v1.0 is implemented exactly as the spec example (same keys, explicit nulls, UTC ISO-8601). Additive optional fields only: `Measurement.failure` (typed reason, omitted when nil) and `clubSnapshot.loftRevision`. Decoding is strict: unknown metric keys, units that do not match the metric, negative speeds/distances, value/provenance mismatches and bad schemaVersion are rejected. | Spec: "Consumers reject NaN/infinity, negative speeds/distances and invalid references." Strictness prevents silent zeros. |
| 2026-10-11 | `CalibrationRecord` field set (scale method, 3x3 transform, camera distance/height/heading, format) is provisional until the G1 capture spike; evolve via `calibrationVersion`. | Spec lists the categories but not the fields; real needs come from physical-device evidence. |
| 2026-10-11 | `Persistence` package: async repository protocols (Session, Calibration, Shot, Ledger) + `PersistenceTestSupport.InMemoryStore` fake in a separate library the app does not link. `commitAccepted(shot, ledger:)` is atomic and idempotent; production stores reject synthetic shots (T13); ledger rows survive shot/session deletion. Club/Bag repository is left to F08 (needs the Bag type). | Keeps the real store (2.1) swappable and the fake out of release builds. |
| 2026-10-11 | Shared formatting layer is the `Formatting` package (`DisplayUnits`, `UnitConversion`, `MetricFormatter`, `NumberInput`): SI in, locale-aware strings out; angles always degrees, spin always rpm; unavailable returns nil (never 0). Unit defaults follow region (US: yd/mph, else m/km/h), not language. | Spec F18/F25: one formatting layer, units separate from language, Swedish decimal comma. |
| 2026-10-11 | App shell: bottom tab bar in portrait, leading rail in landscape (chosen by view size, state in `AppNavigation` so rotation keeps selection); Home/Bag/Progress tabs, Settings via gear (sheet). Design tokens in `App/Theme` (light/dark, contrast unit-tested). Display settings (units, theme) interim in UserDefaults until `UserSettings` persistence (2.1). Language switching (F25) and handedness (F18) are not part of 0.5. | Spec 13/F22 pick one consistent navigation pattern. |
| 2026-10-11 | `Capture` package split: `Capture` (platform-free logic, tested with a fake frame source) and `CaptureAV` (iOS AVFoundation adapter, linked into the app so every verify compiles it). Timing is from presentation timestamps; a gap is an interval >= 1.5x nominal; pause/interrupt returns an incomplete window that is never promoted; frames while paused are ignored and counted. | G1 plan section 5, F04/F23. Keeps camera behaviour behind a protocol boundary until a device can exercise it. |
| 2026-10-11 | G1 harness records **all-intra HEVC** (every frame a key frame, ~100 Mbit/s, real-time VideoToolbox encoder) into a byte-bounded ring buffer, written to `.mov` by passthrough `AVAssetWriter` with original PTS. Raw camera buffers are never retained. | Holding raw `CMSampleBuffer`s starves the camera buffer pool (drops) and ~1 GB/s at 1080p240; all-intra lets any window start at any frame and avoids inter-frame smear. Open: bitrate tuning (plan Q5). |
| 2026-10-11 | Harness UI is developer tooling: verbatim English, not localised, compiled only with `CAPTURE_HARNESS` (Debug). `scripts/check-harness-separation.sh` (part of `verify.sh`) builds Release and Debug and fails if Release contains harness strings or if the Debug positive control finds none. | Keeps debug code out of shipped builds without a vacuous check. |
| 2026-10-12 | `Analysis` package: pure library (timing, mains-flicker DFT with a 20 Hz floor, Laplacian sharpness, grid motion baseline, bright-disc tracker for self-checks, `g1-annotations/1` with validation and P4/P7 counters, manifest-vs-file consistency) plus `g1-analyze` (macOS, AVFoundation decode, streams frames, optional JSON report and annotation template). Exit code 1 if the manifest disagrees with the file. | G1 plan section 5/9 (1.5, A1/A2). The disc tracker is a plumbing self-check and explicitly not the product ball detector. |
| 2026-10-12 | Clip writer uses a 240,000 timescale for movie and media (default 600 quantised 240 fps to alternating 3.3/5 ms steps, found by `g1-analyze` on the D1 clips). Manifest fields added after D1 are optional so old manifests still decode. | Timing analysis must come from honest timestamps; old recordings must stay readable. |
| 2026-10-12 | Real store is **SQLite** (system library, no dependency) behind the existing repository protocols: WAL, `synchronous=FULL`, foreign keys, contract JSON next to query columns, `user_version` migrations applied in one transaction with the version bump, newer databases refused untouched, corrupt files refused untouched, ledger table without a foreign key to shots. Media files live outside the DB (`MediaDirectory`: staging, atomic non-overwriting commit, checksum, orphan scan, path-traversal rejection). SwiftData was not chosen: explicit transactions, crash tests and migration control matter more here. | F20 acceptance: atomic accepted-shot + ledger write, migrations preserve IDs and counts, orphan recovery. |
| 2026-10-12 | Fault hook (`armFault`) exists only in Debug builds; the crash helper executable is never linked into the app. Repository tests run against both backends (parity). | Keeps test hooks out of shipped builds; the fake and the real store cannot drift. |
| 2026-10-12 | F08 implemented with the plan's **defaults for the open questions** (Q1: Club contract extended with brand/model/sortOrder/loftRevision, already recorded; Q2: loft range 1-70 degrees, a putter's loft may stay unset). **Both still need the owner's confirmation.** The bag is stored in the SQLite store (migration v2, `bag` table, one JSON document with its own schema version) instead of the plan's JSON file, because the real store now exists; a bag that cannot be read is an error and is never re-seeded over. | Plan section 7; F20 store available. |
| 2026-10-12 | Editor draft state lives in `BagStore` (not the view) so rotation, which rebuilds the shell, cannot lose typed text. The draft binding ignores writes when no draft exists. | Found by testing: a dismissing sheet's text fields wrote back an empty value and re-opened the editor after a successful save. |
| 2026-10-12 | History (F10) lives in the Progress tab (Sessions | Trends, mockup 08). Every number on the history screens is recomputed from what is stored: a change is written first, then the whole view is rebuilt from the database. Summaries are derived views (`SessionSummaries`), never stored. Averages use only included shots with finite, non-invalid, available values; no data shows "No data", never 0. | F10 acceptance: failed captures cannot contaminate averages; derived summaries are reproducible views (spec 06). |
| 2026-10-12 | Demo data for UI tests (`HistoryFixtures`, `-uiTestSeedHistory`) exists in **Debug builds only**, every shot is marked synthetic and labelled "Demo data" on screen, and the production store refuses synthetic shots (T13). `scripts/check-harness-separation.sh` now also proves Release contains none of it. | Spec F24: demo pipelines are compile-time separated and visibly labelled. |
| 2026-10-12 | Shot actions (Exclude/Restore/Delete) are a long-press menu plus VoiceOver actions, not swipe actions. Permanent deletes need a confirmation. | SwiftUI `swipeActions` on these rows made the third row of a freshly opened session disappear (see EVIDENCE 2.3); a menu is also easier to discover and works with VoiceOver. |
| 2026-10-12 | `HistoryStore.load()` and `BagStore.load()` run once: concurrent callers wait for the load in flight. | Found by test: two overlapping loads would have seeded the bag twice with different club IDs and read a half-seeded history database. |


| 2026-10-12 | Analysis selection is one pure function (`ShotSelection.select`) feeding profiles, gapping, dispersion and comparison | Guarantees list, averages and gaps use the same shot IDs (F10a). |
| 2026-10-12 | Standardised conditions view returns no values without an injected standardiser | No validated flight model yet; recorded numbers must not appear under a Standardised label. |
| 2026-10-12 | Spread ellipse is 1 SD of the covariance, drawn only with 3+ non-collinear lateral points | F10a forbids implying 68/95% coverage; legend must say 1 SD. |
| 2026-10-12 | Exports exclude demo shots, device identifiers and media links by default; excluded shots are kept with their flag | Privacy-preserving defaults (F17) while keeping analysis reproducible. |
| 2026-10-12 | CSV formula escape is an apostrophe prefix on text cells only; numbers are never escaped | Negative numbers must stay numeric; OWASP-style neutralisation for user text such as club names. |
| 2026-10-12 | Flight (3.5) built before 3.1 with generic coefficients and an explicit unvalidated version; total distance not produced; unknown spin gives a lower bound that is not stored as carry | Needs no G1 data and unblocks analytics; avoids inventing spin or runout numbers (F06). |
| 2026-10-12 | Setup diagram puts a right-handed golfer on the far side when the target is on the right | Target must be on the golfer's left; mockup 04 shows the opposite (spec text wins). |
| 2026-10-12 | Unmeasured checks show Not checked and block arming only when nothing at all is measured | Never present absence of data as Good (F02, F06 spirit). |
| 2026-10-12 | A practice session with zero accepted shots is not saved (dropped at End and at crash recovery) | F05: no misleading empty sessions or averages in history. |
| 2026-10-12 | Unavailable modes on Home are labelled Coming soon and are not buttons | No dead ends and no pretending a mode exists. |
| 2026-10-12 | Spoken words are built from the same formatter as the screens and always shown as a caption; muting never hides the text | F07: audio is never the only channel; one formatting layer. |
| 2026-10-12 | Speech is held while a shot is armed, and a newer result replaces an unspoken one | No audio during the next capture window and no backlog recital (F07). |
| 2026-10-13 | Each presented screen applies the app locale itself | A sheet that is already open does not pick up a locale change from its presenter. |
| 2026-10-13 | Manual atmosphere is reported invalid, never replaced by the standard atmosphere | F18/F06: no silent fabricated values. |
| 2026-10-13 | One canonical club order (bag order, then others by name) drives lists, filter sheet and colours | A club must look and sit the same in every F10a screen whatever is selected. |
| 2026-10-13 | A 2D spread shape is drawn only if the shortest axis is at least 10% of the longest | Nearly collinear points make a sliver that looks like a line and means nothing. |
| 2026-10-13 | Segmented pickers become menus and chip rows stack at accessibility text sizes | Segmented controls cannot shrink; sideways scrolling hides options (F22). |
| 2026-10-13 | The localisation key-usage check is part of the gate | A key missing from the catalog shows raw text to the user; stale keys hide untranslated leftovers. |
| 2026-10-13 | Primary buttons use one `PrimaryButtonStyle` with an `onAccent` label colour | White on the lime accent failed contrast in dark mode; one style keeps all five buttons consistent (F22). |
| 2026-10-13 | Club colours are light/dark colour tokens with at least 3:1 contrast | Dots and lines on the plot need contrast in both schemes; symbols still carry the identity. |
| 2026-10-13 | The Apple audit runs with documented exemptions (glass bars, disabled controls, informational clipping) | Findings we cannot attribute to our own views would hide real ones; each exemption is explained in the test. |
| 2026-10-13 | Milestone QA is an automated screen walk plus a human-eye comparison, labelled as self-review | An independent reviewer was not available in this session; the limit is stated in the evidence. |
| 2026-10-13 | Allowance rules live in a pure `Allowance` package; the app only supplies the ledger, the clock and the entitlement | Boundary tests (49/50/51, 9/10/11) run in seconds and do not need StoreKit. |
| 2026-10-13 | The effective clock is the latest of now, the latest time seen and the latest ledger commit | A rolled-back clock must not open an earlier, unspent period. |
| 2026-10-13 | The monthly grant starts the calendar month AFTER the introductory credits run out | F19: no accumulation before exhaustion and no same-month top-up. |
| 2026-10-13 | Nothing arms until the ledger has been read | An unknown balance must not grant access; a failed load blocks and says so. |
| 2026-10-14 | The store sits behind `StoreProviding`; a scripted store (Debug only) drives UI tests | Purchases cannot be automated through the system sheet, and tests must never charge or need a network. |
| 2026-10-14 | A failed or incomplete catalog is "failed" with a retry, never a plan | F19: a loading failure must not look like free access or a zero price. |
| 2026-10-14 | A verified "no entitlement" from the store clears access at once; an unreachable store keeps the cache for seven days | F19: no paid grace after a known revocation, and offline use inside the documented window. |
| 2026-10-14 | The local StoreKit file lives in `Config/`, outside the app bundle | A test fixture must never ship in the app. |
| 2026-10-14 | Terms link is Apple's standard licence until the owner hosts their own | Avoids a dead or invented URL; recorded in the backlog. |
| 2026-10-14 | Redemption unlocks only what StoreKit later reports as verified, never the sheet's result | The sheet cannot tell us whether a code was valid; the store can. |
| 2026-10-14 | "Complimentary" is shown only from verified offer metadata (free offer code); otherwise neutral "Pro" | F19a: do not guess sponsorship. |
| 2026-10-14 | No in-app revoke or disable of redeemed access | F19a: Apple codes cannot be revoked after redemption; a local toggle would be false. |
| 2026-10-15 | Deleting practice data keeps the usage ledger and says so before it happens | F21/F19: deleting data must not reset the free allowance; disclosure is mandatory. |
| 2026-10-15 | Deletion is followed by VACUUM and a truncating WAL checkpoint | A normal DELETE leaves the text in free pages and in the log; a test searches the files for it. |
| 2026-10-15 | The network audit is a static check in the gate until capture exists | No real traffic exists to capture yet; the static check fails the build on any networking API or third-party package. |
| 2026-10-15 | The diagnostic bundle is built on request, previewed in full, and shared only through the system share sheet | F21: no automatic sending; the golfer sees the content first. |
| 2026-10-15 | The commerce store keeps its own latest-time-seen | Expiry decisions must not depend on a clock the user can set back. |
| 2026-10-15 | Short and long count only misses beyond the tolerance | A hit that lands 2 m long is a hit, not a long miss; the average signed error shows any bias. |
| 2026-10-15 | Drills are scored on distance only until sideways landing is validated, and say so | F11/F06: no sideways hit or miss from an unvalidated figure; labelled "Distance only". |
| 2026-10-15 | The drill configuration is stored in the session record | History must show the original drill, not today's settings. |
| 2026-10-15 | Ball and club detection follows `docs/plans/G2-detector-coreml.md`: no-ML baseline first, then Create ML baseline, then our own multi-frame heatmap model; club-head model after the ball model | Owner accepted all plan suggestions (Q1, Q5). Research shows single-frame box detectors fail on real swing video. |
| 2026-10-15 | No external licences in the product: own model, own weights, own consented data, trained locally on the owner's M1 Max and M1 Mac mini; permissive tools for development only | Owner decision (Q2, Q4). Avoids AGPL and dataset terms; keeps golfers' clips on the owner's machines. |
| 2026-10-15 | Metric policy from one side-on phone: ball speed, vertical launch and club speed measured after G2; horizontal launch and attack angle experimental until G2; spin estimated (marked-ball research track); club path research-only; smash factor derived only from two measured speeds; failed metrics ship as unavailable | Owner accepted (Q8-Q10). Left/right is depth for a side-on camera and only weakly observable. |
| 2026-10-15 | `clubPath` added to the metric catalogue (additive) with G2 targets attack angle MAE ≤1.5 deg, club path MAE ≤2 deg, smash factor MAE ≤0.08 | Owner accepted (Q8); implemented when club work starts (E23). |
| 2026-10-15 | Golfers' clips used for training only with written consent, kept local, pseudonymous, deleted on withdrawal; white balls at launch, other colours as their own stratum | Owner accepted (Q3, Q6). |
